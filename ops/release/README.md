# Release build and activation

`build_release.sh` accepts only a clean canonical `main` checkout, serializes builds, compiles/tests the backend, builds the frontend, and produces an immutable source/frontend/test manifest bundle under `/opt/apps/posterpro/releases/` (override with `POSTERPRO_RELEASE_ROOT`). It does not install dependencies. Set `POSTERPRO_PYTHON` and `POSTERPRO_PYTEST` to a reviewed environment.

For frontend and browser-extension-only changes, `build_frontend_release.sh` runs the frontend test suite, builds the Next standalone runtime, and runs the extension pairing bridge test when that source changed. It reuses the active immutable release's backend virtual environment and backend/bridge test evidence only after checking that backend and bridge sources, migrations, Python and Node lockfiles, and Node runtime declaration are byte-identical. The release manifest records which tests were run and which were reused, plus the source hashes and original evidence hash. Any backend, bridge, migration, or runtime-lock change is rejected from this fast path and must use the full runtime builder. Test/build output is kept in the release artifact, not the canonical checkout.

The first clean GitHub-lineage release may use `source-lineage-baseline.json` only when `verify_lineage_transition.py` proves that the active release source and the public GitHub base have identical production application source fingerprints. The activation guard repeats that proof against the exact active release and candidate. This transition does not rewrite or force-push public history. The old local source checkout is retained as an archive; `/opt/apps/posterpro/canonical` on `main` and GitHub `main` are the active source line.

`activate_release.sh` acquires a deployment lock, checks the release manifest and parsed UTC build time (ISO 8601 or compact UTC), atomically switches a configured active symlink, restarts explicitly configured services, retries bounded health checks through startup, and rolls the symlink back on restart/health failure. It refuses manifests requiring approval. Physical printing is recorded disabled by the build script.

The full `build_runtime_release.sh` remains the required path for backend, worker, bridge, or migration changes and emits a candidate that must pass the runtime and migration release gates. The frontend fast path emits a production release only for compatible UI/extension-only changes based on the currently active, checksummed immutable release. Activation verifies the candidate's checksums, chronology, source ancestry or the one-time verified lineage transition, serialized lock, and bounded public health checks; failed health restores the previous symlink and restarts the configured service set on that release.

Canonical development checkout: `/opt/apps/posterpro/canonical`, branch `main`, tracking `https://github.com/mattysparkles/PosterPro.git`. The previous `/opt/apps/posterpro/integration-20261110` checkout is retained as an archival reference and must not be used for builds or future feature work.
